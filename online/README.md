# 联机测试版（Supabase 免费版）

这是最小可用的网页联机版本：**房间号对战、双方各执一方、默认 12×9 棋盘、无 AI、无撤销**。
后端用 Supabase 免费计划的 PostgreSQL + 自动生成的 REST API，前端不引入任何依赖，只用 `fetch` 轮询（约 1 秒一次）。

规则引擎与单机版共用同一份 `js/engine.js`：后端只存一串有序着法，两边各自重放得到棋局，所以刷新、换设备、中途加入都只是"重新拉一次列表"。

## 第一步：零配置先跑通（30 秒）

1. 启动本地服务器：

   ```powershell
   cd "E:\Code\Web\Way Creating Chess"
   node tools\serve.mjs
   ```

2. 打开 <http://localhost:8000/online/>，平台选 **本地标签页测试（零配置）**，房间号随便填（例如 `TEST`），我执 **A**，点 **进入房间**。
3. 在同一个浏览器里再开一个标签页，打开同一地址，房间号填一样的 `TEST`，我执 **B**，点 **进入房间**。
4. 两个标签页就能对着下（A 先手）。这一步不需要任何账号，用来确认整个流程没问题。

## 第二步：开通 Supabase 免费云端房间（约 5 分钟）

### 1. 建项目

1. 打开 <https://supabase.com>，用 GitHub 或邮箱注册（免费计划不需要信用卡）。
2. 点 **New project**，填项目名（例如 `way-chess`）、数据库密码、Region 选 **Southeast Asia (Singapore)**（国内访问较快），创建后等 1–2 分钟初始化。

### 2. 建表（复制粘贴这段 SQL）

左侧 **SQL Editor → New query**，粘贴下面的 SQL，点 **Run**：

```sql
create table if not exists public.moves (
  id bigint generated by default as identity primary key,
  room text not null,
  move_index integer not null,
  side smallint not null,
  x smallint not null,
  y smallint not null,
  created_at timestamptz not null default now(),
  constraint moves_room_index_unique unique (room, move_index)
);

alter table public.moves enable row level security;

drop policy if exists "online test read" on public.moves;
drop policy if exists "online test write" on public.moves;
drop policy if exists "online test delete" on public.moves;

create policy "online test read" on public.moves for select to anon using (true);
create policy "online test write" on public.moves for insert to anon with check (true);
create policy "online test delete" on public.moves for delete to anon using (true);

grant select, insert, delete on public.moves to anon;
grant usage, select on all sequences in schema public to anon;
```

表结构说明：`room` 是房间号，`move_index` 是第几手（从 0 开始），`side` 是 2（A）或 3（B），`x`/`y` 是格子坐标。
`unique (room, move_index)` 保证了两个人同时落子时只有一手能成功，另一手会收到 409，然后自动重新同步。

### 3. 拿两个值

左侧 **Project Settings → API**：

- **Project URL**：形如 `https://abcdxyz.supabase.co`
- **anon public** 或 **Publishable key**：一长串 `eyJ...` 或 `sb_publishable_...`

### 4. 在页面里填上

打开 <http://localhost:8000/online/>：

1. 平台选 **Supabase 云端房间（免费）**；
2. 填入 Project URL 和 key，房间号自己起一个（例如 `ABCD`）；
3. 我执 **A**，点 **进入房间**；
4. 点 **复制邀请链接**，把链接发给对手；他打开链接会自动填入同样的房间和 key，他的身份选 **B** 即可。

> 邀请链接里带着 anon key。它是**公开**密钥（本来就发在前端代码里，权限由 RLS 策略决定），但别把 `service_role` / secret key 放进任何前端文件。

## 第三步：部署到 GitHub Pages

联机页和单机版在同一个站点里，按原来的方式推送即可（Settings → Pages → Deploy from a branch → `main` / root），
之后访问 `https://<用户名>.github.io/<仓库名>/online/`。

如果对手在国内、而 GitHub Pages 打不开，可以把整个目录同时放到任意静态托管上（例如 Cloudflare Pages、Netlify），前端指向同一个 Supabase 项目即可。

## 常见问题

| 现象 | 原因与处理 |
| --- | --- |
| 提示 `读取着法失败：HTTP 401/403` | key 填错或用了 secret key；确认填的是 **anon public / Publishable**，并在 SQL Editor 里执行过上面那段策略 |
| 提示 `写入着法失败：HTTP 404` | 表没建成功；确认表名是 `public.moves`，且 SQL 那段没有报错 |
| 两边都能落子但不是同一盘棋 | 房间号不一致（区分大小写，页面会统一转成大写）；点"立即同步"看同步时间是否在跳 |
| 页面一直"等待 X 方落子" | 对手还没进入房间，或者他同步报错（看他的提示行） |
| 想重开一局 | 点 **清空本房间**（只清这个房间号的着法）；或者换个房间号 |
| 免费项目会不会休眠 | Supabase 免费项目**约 7 天没有活动会被暂停**，控制台点一下即可恢复；对局期间不会有问题 |
| 延迟 | 云端模式约 1 秒轮询一次，新加坡节点国内往返通常 100–300ms，回合制完全够用；想更快可以把轮询间隔调小（`online/online.js` 里的 `POLL_REMOTE_MS`） |

## 这个测试版的限制（有意为之）

- **不是服务端权威**：客户端各自校验，理论上可以改前端作弊。朋友之间娱乐够用，公开匹配则要把这段逻辑挪到服务端（可直接复用在 Node 上 `import` 这份 `engine.js`）。
- 固定默认棋盘，没有 AI、没有撤销、没有计时、没有观战、没有断线自动重连（刷新即可恢复，因为棋局是从着法列表重放的）。
- 所有人都能读写 `moves` 表（测试用策略）。正式上线应加匿名登录 + 更细的策略，或改成自建 WebSocket 服务器。

## 想继续扩展时

1. **自定义棋盘**：新建 `rooms` 表存棋盘定义（或随机种子），加入时先读房间再读着法即可。
2. **撤销**：加一类"请求/同意"消息行，服务端权威时由服务端执行。
3. **服务端权威**：写一个 60 行的 Node + `ws` 服务器，`import './js/engine.js'` 校验每一手，前端把 `transports.js` 换成 WebSocket 实现即可（接口只有 `list` / `append` / `clear`）。
4. **人机混合**：房间里加一个"AI 补位"开关，由房主触发本地 AI 落子（复用单机版 `js/ai.js`）。
